# AI 캐릭터 시트 생성 기준

이 문서는 WhatsNext 관리자 자동 생성기가 `POST /api/admin/characters`에 보낼 캐릭터 시트의 작성 기준이다. 완성된 캐릭터 설정은 요청 본문의 `system_prompt`에 저장된다. 서비스의 채팅 모델은 이 값을 그대로 읽으므로, 짧은 홍보 문구보다 대화 중 지킬 수 있는 구체적인 규칙을 작성한다.

기존 시트의 참고 자료: [Google Drive 캐릭터 시트 폴더](https://drive.google.com/drive/folders/1PNa0uLN93PWyoUs3LEz_6VtfX72Corog). 날짜별 KO/EN 시트와 전체 마스터의 `Deep character sheet · live dialogue rules / 심화 캐릭터 시트`를 함께 확인한다. Drive 자료는 작성 참고용이며, 이 저장소의 MD 파일을 수정하는 것만으로 이미 공개된 캐릭터의 데이터베이스 `system_prompt`가 바뀌지는 않는다.

## 생성 목표

- 한 시트의 중심은 **캐릭터 한 명과 `{{user}}`의 대화**다. 조연은 세계와 사건의 배경으로만 등장시키고, 다른 주연의 발화를 매 턴 강제로 출력하지 않는다.
- 같은 직업·장르·관계 소재라도 성격, 말투, 방어 방식, 약점, 선택의 비용, 관계가 변하는 속도가 달라야 한다. 이름이나 배경만 바꾼 시트는 폐기한다.
- 평범한 대화, 단둘이 있는 순간, 위기, 거절, 질투나 신뢰가 시험받는 상황에서 **서로 다른 반응**을 적는다. `냉정하지만 다정하다` 같은 형용사만으로 끝내지 않는다.
- 각 사실을 실제 채팅의 선택과 결과로 연결한다. 직업이 있다면 일정·책임·금기·말하는 방식에 영향을 주고, 비밀이 있다면 숨기는 이유와 드러나는 조건이 있어야 한다.
- `system_prompt`는 한 캐릭터당 캐릭터별로 필요한 만큼 충분한 분량을 목표로 한다. 불필요한 반복으로 글자 수를 채우지 않는다. 정보가 부족한 항목은 지어내지 말고 생성 단계에서 조사·설계를 보강한다.

## 작성 순서와 필수 내용

### 1. 정체성과 현재 상황

이름, 나이 또는 삶의 단계, 직업·역할, 살아가는 장소, 장르, 이야기 시작 시점, 지금 당장 처리해야 할 문제를 적는다. 생일·혈액형처럼 장면에 쓰이지 않는 값은 억지로 채우지 않는다. 외모는 시각적으로 구별되는 특징과 피로·긴장·기쁨에 따라 달라지는 신호를 함께 적는다.

### 2. 성격의 원인과 모순

겉으로 보이는 성격과 혼자 있을 때의 성격을 나눈다. 원하는 것, 잃기 두려운 것, 그것을 숨기기 위해 쓰는 방어 방식, 절대 쉽게 넘지 않는 선, 스스로도 인정하기 싫은 욕구를 연결한다. MBTI나 애니어그램은 행동 설명에 도움이 될 때만 쓴다. `자존심이 강하다`면 사과를 미루는 구체적인 행동과 끝내 사과하게 만드는 조건까지 적는다.

### 3. 조건부 행동 규칙

공적인 자리 / `{{user}}`와 단둘이 있을 때 / 압박을 받을 때 / 기대가 어긋날 때 / 도움을 받거나 거절당할 때의 반응을 각각 적는다. 추상적인 명령보다 관찰 가능한 변화가 좋다. 예를 들어 **감정이 커질수록 말수가 줄고 장갑 끝을 당긴다**처럼 말의 길이와 몸짓이 함께 바뀌어야 한다. 규칙끼리 충돌할 경우 무엇이 우선인지 정한다.

### 4. 말투와 예시 대화

기본 호칭, 존댓말·반말, 문장 길이, 자주 생략하는 말, 유머의 방식, 질문과 명령의 비율을 정한다. 차분할 때와 흔들릴 때의 차이를 쓴다. 첫 인사와 최소 세 가지 상황별 짧은 대화 예시를 넣는다: 일상, 갈등, 약점이 드러난 순간. 예시는 모델의 **말투 기준**이며 이미 일어난 사건으로 취급하지 않는다. 같은 대사를 반복하지 않게 한다.

### 5. `{{user}}`와의 관계

처음 만났을 때의 역할과 거리, 서로에게 기대하는 것, 불신 또는 끌림의 이유, 비밀, 신뢰가 오르는 행동, 신뢰가 깨지는 행동을 적는다. 관계 변화는 사건과 사용자의 선택이 누적된 결과로만 표현한다. 한 번의 친절로 깊은 신뢰·연애·집착으로 급변하지 않는다. 캐릭터는 사용자의 행동에 반응하되 사용자 대사, 감정, 결정을 대신 서술하지 않는다.

### 6. 세계와 이야기의 압력

시대·장소·조직·능력·사회 규칙은 이야기의 인과관계에 필요한 만큼 상세히 적는다. 세계가 유지되는 원리와 지금 깨질 위험이 있는 균형을 적고, 캐릭터의 직업과 관계에 어떤 비용을 만드는지 명시한다. 주거·일과·취향·버릇은 반복 가능한 장면의 재료로 연결한다. 세계관만 화려하고 캐릭터의 선택에 영향을 주지 않는 설정은 줄인다.

### 7. 장면 운영

각 답변은 현재 시간·장소·목표와 이어져야 한다. 한 턴에는 구체적인 행동 또는 감각, 캐릭터다운 반응, 작지만 실제로 바뀐 결과를 담고 사용자가 답할 여지를 남긴다. 상태·호감도·일기·명령어 같은 장치는 그 캐릭터의 이야기에서 실제로 필요할 때만 정의하고, 모든 캐릭터에 공통 장치처럼 복사하지 않는다. 시간 점프 뒤에는 위치, 약속, 부상, 비밀, 관계의 변화를 일관되게 추적한다.

## `system_prompt` 권장 뼈대

아래 제목은 내부 생성기의 작성 순서다. 각 칸에 한 문장만 넣지 말고 위의 원인·조건·결과를 채운다.

```md
# 캐릭터 기본과 현재 상황
이름 / 역할 / 장르 / 시작 장소와 시간 / 당장 해결해야 할 문제

# 외형과 감각
구별되는 모습 / 상태에 따른 변화 / 목소리와 버릇

# 성격과 심리
표면 / 사적인 모습 / 핵심 욕구 / 두려움 / 방어 방식 / 모순

# 말투
호칭 / 문장 길이 / 일상·갈등·취약할 때의 어조 / 피할 표현

# {{user}}와의 관계
시작 거리 / 원하는 것 / 신뢰가 변하는 조건 / 남아 있는 저항

# 세계관과 생활
직업의 제약 / 장소·조직·능력 규칙 / 일과 / 진행 중인 갈등

# 상황별 행동 규칙
공적 자리 / 단둘이 / 압박 / 거절 / 돌봄 / 관계 시험

# 이야기 진행 규칙
시점 / 시간·장소 추적 / 사용자 선택권 / 장면의 결과

# 첫 장면과 대화 예시
인트로 / 일상 / 갈등 / 약점이 드러난 순간
```

## 생성 후 품질 점검

1. 이름·직업·장르를 지우고 읽어도 이 인물만의 말투와 행동을 구별할 수 있는가?
2. 평소·갈등·취약한 장면의 반응이 실제로 다른가? 각 차이는 기존 설정에서 설명되는가?
3. 첫 대화에서 아직 얻지 못한 신뢰나 비밀을 이미 가진 것처럼 말하지 않는가?
4. 외형·습관·취향이 대화에 영향을 주는가? 단순한 목록이나 매 턴 반복하는 장식은 아닌가?
5. `{{user}}`에게 선택권을 남기는가? 사용자 대사나 감정을 대신 쓰지 않는가?
6. 다른 캐릭터의 문장, 명령어, 관계 훅이 섞이지 않았는가?
7. `system_prompt`, `introTurns`, `suggestions`, `short_intro`가 같은 시작 상황을 가리키는가?

검사를 통과하지 못하면 문장을 늘리기보다 **원인, 상황별 반응, 말투 예시, 선택의 결과**를 다시 설계한다.

## 서비스 세이프티 모드

성적인 노골적 대화와 잔혹한 폭력 장면은 생성 지침에 포함하지 않는다. 사용자가 요청하거나 모델이 그런 내용을 생성할 때 채팅 UI가 해당 대화를 표시하지 않고 안내 메시지와 스낵바를 보여준다. 현재 클라이언트 검사는 1차 방어이며, 별도 소켓 채팅 서버에도 동일한 입력·출력 검사를 적용해야 직접 API 호출과 저장 단계까지 차단할 수 있다.
